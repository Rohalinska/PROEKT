# SportsLeague - Професійна Турнірна Система Ліги

Графічна інтерактивна веб-оболонка для автоматизації, симуляції та керування футбольними чемпіонатами. Проєкт реалізовано як демонстрацію практичного застосування об'єктно-орієнтованого проєктування (ООП), архітектурних патернів та суворих критеріїв SOLID.

** Варіант реалізації: №14**

---

## Стек технологій
* **Платформа:** .NET (C#)
* **Фреймворк:** Blazor WebAssembly / Razor Components
* **Тестування:** xUnit (Методологія AAA: Arrange-Act-Assert)
* **Серіалізація даних:** System.Text.Json (взаємодія через DTO)

---

## Реалізовані архітектурні патерни (Design Patterns)

Проєкт побудовано на базі сучасних шаблонів проєктування для забезпечення гнучкості та слабкої зв'язаності компонентів (Loose Coupling):

| Патерн | Компонент у коді | Опис та призначення |
| :--- | :--- | :--- |
| **Facade (Фасад)** | `LeagueManagerFacade` | Уніфікований інтерфейс, який спрощує взаємодію UI-шару з репозиторіями матчів, команд та стратегіями. |
| **Strategy (Стратегія)** | `IScoreStrategy`, `FootballClassicStrategy` | Дозволяє динамічно змінювати правила нарахування очок (напр., класична схема FIFA `3-1-0` або агресивний регламент `2-0-0`). |
| **Factory (Фабрика)** | `Facade.CreateStrategy()` | Інкапсулює логіку створення об'єктів-стратегій на основі вибору користувача в інтерфейсі. |
| **State (Стан)** | `SeasonContext`, `CurrentState` | Керує життєвим циклом та фазами футбольного сезону, змінюючи доступну логіку при переході між стадіями. |
| **Template Method** | `TournamentReglement`, `UkrainianLeagueReglement` | Визначає скелет алгоритму проведення турніру. Включає обов'язкові кроки безпеки та реакції на повітряні тривоги. |

---

## Ключовий функціонал

1.  **Динамічна симуляція турів:** Можливість генерації та миттєвого розрахунку результатів матчів ліги за обраною турнірною стратегією.
2.  **Складний LINQ-аналіз:** * Динамічне сортування та формування турнірної таблиці в реальному часі.
    * Глибока агрегація даних (підрахунок сумарної кількості голів у сезоні за допомогою розширюваних методів LINQ).
3.  **Перевантаження операторів:** Реалізовано зручне додавання гравців до складу команд через оператор `+` (`Team += Player`), а також порівняння об'єктів через `==`.
4.  **Синхронізація та Retry Policy:** Надійна робота з даними завдяки впровадженню політики повторних спроб (Retry) при збереженні конфігурацій.
5.  **Контроль якості (Автотести):** Інтегрований модуль тестування на базі **xUnit**, який перевіряє коректність бізнес-логіки за стандартом **AAA (Arrange, Act, Assert)** прямо з інтерфейсу.

## Структура проєкту та папки `wwwroot`

Проєкт використовує стандартну архітектуру веб-додатків ASP.NET Core / Blazor:
* `/Domain` - базові сутності (Team, Player, Match).
* `/BusinessLogic` - реалізація патернів, стратегій та фасадів.
* `/Pages` - інтерфейс користувача (`Home.razor`).
* `/wwwroot` - корінь статичних файлів сайту.
    * `index.html` - головна точка входу для браузера.
    * `alexandra.jpg` - локальний статичний ресурс (фотографія розробника).
